# Experimental Methodology & Synthetic Scenarios

## 1. Experimental Setup
All experiments are executed using synthetic audit logs generated by `detection/dataset_generator.py` to ensure complete ethical safety and zero privacy exposure.

---

## 2. Tested Activity Scenarios

| Scenario ID | Scenario Name | Pattern Description | Target Label |
| :--- | :--- | :--- | :--- |
| **Scenario A** | Normal Paper Setter | Regular working hours, single IP, low request frequency (1-3 req/h). | Normal (0) |
| **Scenario B** | Normal Moderator | Moderation review window, valid permissions, standard browser headers. | Normal (0) |
| **Scenario C** | Normal Exam Controller | Scheduling paper release within working hours, single device. | Normal (0) |
| **Scenario D** | Normal Printing Staff | Accessing paper strictly after scheduled release time. | Normal (0) |
| **Scenario E** | Failed Logins Burst | > 10 failed login attempts within 5 minutes from single IP. | Anomalous (1) |
| **Scenario F** | Unauthorized Paper Access | User attempting access to papers assigned to different departments. | Anomalous (1) |
| **Scenario G** | Pre-Release Access Attempt | Attempting paper view/print 45 minutes prior to scheduled release. | Anomalous (1) |
| **Scenario H** | Late-Night Access Spike | Accessing sensitive papers between 2:00 AM and 4:00 AM. | Anomalous (1) |
| **Scenario I** | Rapid Request Rate | High-frequency API polling (> 50 requests/min). | Anomalous (1) |
| **Scenario J** | Multi-IP/Device Roaming | Rapid switching across 5 different IP addresses in 10 minutes. | Anomalous (1) |
| **Scenario K** | Multi-Paper Access Sweep | User attempting to download all stored question papers simultaneously. | Anomalous (1) |
| **Scenario L** | Suspicious Printing Burst | Printing staff initiating multiple print jobs in rapid succession. | Anomalous (1) |
| **Scenario M** | **Evasive / Stealth Behavior** | Low request frequency (3-5 req/h), spread out intervals (300s delay), single failed login, subtle pre-release view attempt designed to evade fixed thresholds. | Anomalous (1) |

---

## 3. Comparative Research Findings
- **Rule-Based Baseline Engine**: Highly effective at detecting loud anomalies (Scenarios E, I, J, K), but suffers from high False Negative Rate (FNR) when evaluated on Evasive Scenario M because request counters remain below fixed threshold limits.
- **Random Forest Classifier**: Achieves superior balance across overall metrics and stealth scenarios, capturing non-linear interactions between `evasive_stealth_index`, `avg_request_interval_sec`, and `is_pre_release_attempt`.
- **Isolation Forest**: Detects novel anomaly clusters without ground-truth training labels, though requires threshold calibration to control False Positive Rate (FPR).
