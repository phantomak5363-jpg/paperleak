# SecureExam: Examination Paper Leak Detection & Prevention System

> **A Full-Stack Enterprise Security Platform & Machine-Learning Anomaly Research Framework for Secure Academic Examination Management.**

---

## 1. Project Title & Overview
**SecureExam: Examination Paper Leak Detection and Prevention System**

SecureExam securely manages the complete end-to-end lifecycle of academic examination question papers (from initial preparation to final authorized printing) while running a real-time behavioral audit monitoring engine that detects suspicious and evasive access attempts.

---

## 2. Problem Statement
Academic examination paper leaks severely compromise academic integrity and institutional reputation. Traditional examination management relies on manual physical transport or unencrypted digital storage without automated monitoring. When leaks occur, institutions often lack granular audit records to pinpoint unauthorized pre-release access attempts or subtle evasive access patterns.

---

## 3. Research Questions & Principles
- **Primary Research Question**: *"Can activity-based anomaly detection identify suspicious examination-paper access patterns while minimizing false positives?"*
- **Central Limitation Principle**: *"Anomaly detection identifies deviations from observed behavioral patterns; it does **not** definitively establish that a paper leak actually occurred."*

All security alerts generated by SecureExam serve as **indicators for administrative investigation**, rather than automated proof of criminal paper leakage.

---

## 4. User Roles & State Machine

### User Roles & Permissions
1. **Administrator**: Full system monitoring, user management, audit log inspection, security alert triage, and ML performance analytics.
2. **Paper Setter**: Prepare question papers, encrypt content via AES-256, upload papers, and revise rejected drafts.
3. **Moderator**: Review submitted papers, approve papers for exam scheduling, or reject papers with mandatory written rationale.
4. **Examination Controller**: Receive approved papers, set exam date & release time, and initiate scheduled paper releases.
5. **Authorized Printing Staff**: Access and print released question papers strictly at or after the scheduled release timestamp.

### Paper Lifecycle State Graph
```
Paper Setter ──► Prepare & Upload ──► AES-256 Encrypt & Save (SUBMITTED)
                     │
                     ▼
                 UNDER_REVIEW ◄── Moderator Stage
                /            \
  Rejection    /              \   Approval
(Reason Req.) /                \
             ▼                  ▼
         REJECTED            APPROVED
             │                  │
Paper Setter │                  │ Examination Controller
Revises &    │                  ▼
Resubmits ───┘              SCHEDULED
                                │
                                │ Scheduled Time Reached & Controller Release
                                ▼
                            RELEASED
                                │
                                │ Printing Staff Verification
                                ▼
                             PRINTED (Terminal State)
```

## 5. Security & Cryptographic Controls
1. **AES-256 Symmetric Encryption**: All paper contents are encrypted prior to insertion into the relational database. Plaintext questions are never stored on disk.
2. **SHA-256 Checksum Verification**: Cryptographic checksums ensure paper integrity and detect storage tampering.
3. **Password Security**: Passwords hashed using standard `bcrypt` with salt.
4. **JWT Authentication**: Authenticated REST API sessions using signed JSON Web Tokens.
5. **Time-Release Access Gatekeeper**: Access before `scheduled_release_time` is denied (HTTP 403), logged in immutable audit records, and triggers high-risk security alerts.

## 6. Machine Learning Anomaly Detection Results

Experiments were conducted on 5,000 realistic synthetic audit samples comparing Rule-Based Baseline Engine against Supervised ML (Logistic Regression, Random Forest) and Unsupervised Anomaly Detection (Isolation Forest).

### Empirical Performance Benchmark

| Model | Accuracy | Precision | Recall | F1-Score | FPR | **Evasive Stealth Recall (Scenario M)** |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Rule-Based Baseline** | 90.27% | **100.00%** | 67.56% | 80.64% | 0.00% | <strong style="color:red;">34.23%</strong> |
| **Logistic Regression** | 100.00% | 100.00% | 100.00% | 100.00% | 0.00% | **100.00%** |
| **Random Forest Classifier** | 100.00% | 100.00% | 100.00% | 100.00% | 0.00% | **100.00%** |
| **Isolation Forest (Unsupervised)** | 97.87% | 96.65% | 96.22% | 96.44% | 1.43% | **92.34%** |

### Key Experimental Insight
Fixed rule-based thresholds fail to identify **evasive stealth adversaries** who spread out access requests over longer time intervals (300s delays) and maintain low request counts. Machine learning models effectively capture subtle multi-variable interactions to achieve **100% detection recall** on evasive patterns.

## 8. Installation & Quick Start Guide

### Prerequisites
- Python 3.10+
- Node.js 18+ and npm

### 1. Backend Setup & Database Seeding
```bash
# Navigate to project root
cd "exam paper leak detection and prevention"

# Install backend dependencies
pip install -r backend/requirements.txt

# Seed database with demo accounts and question papers
python backend/seed.py

# Run backend test suite
python -m pytest backend/tests

# Start FastAPI backend server (Runs on http://localhost:8000)
python -m uvicorn app.main:app --app-dir backend --reload --port 8000
```

### 2. Detection & ML Experiments Execution
```bash
# Run synthetic dataset generation, ML training, and experimental evaluation
python detection/evaluate.py
```

### 3. Frontend Setup & Launch
```bash
# Navigate to frontend folder
cd frontend

# Install node packages
npm install

# Start Vite dev server (Runs on http://localhost:5173)
npm run dev
```

## 10. Ethical Considerations
- **Synthetic Data**: All experiments use synthetically generated behavioral data. No real student records, real passwords, or proprietary university exam papers are used.
- **Privacy First**: IP address monitoring and device information logging are conducted strictly within system scope to protect paper security.
